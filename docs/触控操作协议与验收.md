# 《一人不撤》触控操作协议与验收

> 版本：2026-08-28。本文把公开移动 FPS 的通用操作原则转成当前项目自己的触控协议，不复制第三方游戏的界面、文案、图标或素材。

## 1. 触点职责

| 区域/控件 | 默认职责 | 触点规则 |
| --- | --- | --- |
| 左半屏浮动摇杆 | 移动、蹲伏/卧姿下匍匐 | 按下位置生成摇杆，单根触点 owner；松手立即归零 |
| 右半屏空白区域 | 视角 | 只接受右半屏起始触点；按屏幕方向转换为内容坐标 |
| 右侧 FIRE | 开火、按住连发、拖动追枪 | 独立开火 owner；允许拖动时同步消费视角增量 |
| 左侧 FIRE | 三指/四指布局下独立开火 | 独立开火 owner；不消费视角拖动 |
| 跳、蹲、卧、换弹、切枪、开镜 | 离散动作 | 每个控件最多接受一根活动触点；卧倒时第一次跳为起身 |
| 暂停、设置 | 系统入口 | 进入前统一释放游戏输入；设置态只允许纵向滚动 |

左右 FIRE 是两个可选操作位置，不要求玩家同时按下。两个键共享开火状态 owner：已有人开火时，第二个按下会被忽略并立即清理其局部 Pointer/Touch owner，原按键释放后第二个按键可重新接管。

## 2. 事件兼容

- 支持 Pointer Events，并保留 Touch Events 作为 Pointer 构造器存在但不派发触摸 pointer 的 WebView 回退。
- 目标控件和 `document`/`window` 都监听必要的结束、取消、失焦和切后台路径，避免漏 `pointerup` 后持续开火或摇杆卡住。
- Pointer/Touch 双路径只抑制同一位置的重复触点；同一事件包含第二根新手指时必须放行。
- 文档级视角监听不要求 `Touch.target` 存在，先用 `elementFromPoint`，再用控件可视矩形排除动作触点。
- 游戏态全局禁止浏览器手势；设置态恢复 `overflow-y:auto` 与 `touch-action:pan-y`，旋转 WebView 另有 `scrollTop` 手动兜底。

## 3. 灵敏度与反馈

- 视角采用固定线性增量，当前基础触屏灵敏度为 `0.010`，设置倍率为 `70%～150%`；开镜和右 FIRE 拖动分别叠加自己的倍率。
- 摇杆有小死区、约 80% 行程满速和非线性响应，避免轻推无反馈，也避免必须推到边缘才满速。
- 右 FIRE 的按住拖动反馈为视角连续增量；左 FIRE 只反馈开火，不改变视角。
- 任意游戏入口切换、死亡、暂停、设置、结算、失焦和切后台都应停止开火、清空移动按键、复位视角触点和摇杆。

## 4. 验收动作

1. 两指：左摇杆移动 + 右半屏滑动视角，两个方向都不丢输入。
2. 三指：左摇杆移动 + 右 FIRE 开火追枪 + 右侧动作键，松开任意一指不影响其他 owner。
3. 左 FIRE：按住开火并拖动，玩家视角不因该触点改变；松手立即停止。
4. 右 FIRE：按住开火并拖动，视角连续改变；滑出按钮、切后台或打开设置后不持续开火。
5. 双 FIRE：先按右 FIRE，再按左 FIRE；左键被安全忽略；右键松开后再次按左 FIRE 可以接管。
6. 旋转 WebView：右侧视角、左侧摇杆和设置页滚动均按当前屏幕方向工作，不把左侧动作触点误当成视角。
